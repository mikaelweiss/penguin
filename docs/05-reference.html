Reference

An Nx workspace with two projects. packages/engine is the whole of Penguin, and apps/docs serves the pages you are reading. 

penguin/
├── apps/
│   └── docs/                 this site: reads docs/ and serves it
├── docs/                     the html pages
├── packages/
│   └── engine/
│       ├── src/
│       │   ├── core/         what a workflow and an adapter are
│       │   ├── catalog/      finding and loading definitions
│       │   ├── host.ts       cwd, state, shell, exec
│       │   └── paths.ts      where penguin's folders live
│       └── examples/         the starter catalog
├── nx.json
├── tsconfig.json
└── package.json              bun workspaces: apps/*, packages/*

What penguin exports

Definition files import penguin. A frontend imports penguin/catalog.

Name Signature Does
workflow (definition) => definition Checks the description is non-blank, then returns the object.
adapter (definition) => definition Checks role, name, description, and build.
call (ctx, child, params) => Promise<R> Parses the child's params and runs it with the same adapters.
PenguinError class extends Error Penguin refusing. Nothing else subclasses it.
messageOf (error: unknown) => string The message of a caught value, whatever it turned out to be. 
interface Adapters {}

type Ctx<Params> = { params: Params } & Adapters;

type Workflow<Schema extends z.ZodObject = z.ZodObject, R = unknown> = {
  description: string;
  params: Schema;
  run(ctx: Ctx<z.infer<Schema>>): Promise<R>;
};

type Adapter<A = unknown> = {
  role: string;
  name: string;
  description: string;
  build(host: Host): A;
};

type Host = {
  cwd: string;
  state: string;
  shell(cmd: string, options?: ShellOptions): Promise<CommandResult>;
  exec(argv: string[], options?: ExecOptions): Promise<number>;
};

type CommandResult = { code: number; stdout: string; stderr: string };

type ShellOptions = { cwd?: string; stdin?: string };

type ExecOptions = ShellOptions & {
  onOutput?: (chunk: string, stream: "stdout" | "stderr") => void;
};

Adapters is empty on purpose. A catalog widens it by declaration merging, which is the only way ctx.vcs gets a type.

penguin/catalog

Re-exports the errors and the path helpers, plus everything below.

Export Answers
roots(cwd) The catalogs to scan, in order.
projectCatalog, homeCatalog, starterCatalog One catalog each.
workflowsDir, adaptersDir The two subfolders of a catalog.
installed(cwd), installedIn(list) Every adapter found, deduped by role and name.
pick(list, role, name?) { found } | { missing } | { conflict }
defaults() The role-to-name map from ~/.penguin/defaults.
found(cwd), locate(name, cwd) Workflow files, all of them or the first by name.
searchedWorkflows, searchedAdapters Which folders were looked in, for an error message.
load(file), loadAdapter(file) A validated definition, or PenguinError.
Catalog, CatalogScope, AdapterFound, WorkflowFound, Picked The shapes the above return.

createHost is not exported by either entry point. examples/run.ts imports it by path. A frontend outside this repository would need it exported, or its own Host. The type is four members, so building one by hand is reasonable.

Workspace conventions

  • Bun workspaces cover apps/* and packages/*. A folder becomes a project by having a package.json.
  • Nx tags declare boundaries. The engine is scope:engine and may only depend on scope:engine, enforced by @nx/enforce-module-boundaries in eslint.config.js.
  • The root tsconfig.json maps penguin to packages/engine/src/core/index.ts, so the starter definition files type-check in place.
  • examples/ is excluded from lint, because those files import penguin and zod as bare names that only exist at run time.
  • bun run check is tsc --noEmit followed by eslint ..

Running this site

bun run docs         # nx serve docs, on http://localhost:5656

apps/docs reads the docs/ folder on every request, so an edit shows up on reload. Point it somewhere else with PENGUIN_DOCS_DIR, and change the port with PORT. A leading number on a file orders it in the sidebar and never appears in the URL or the title.
