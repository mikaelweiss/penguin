Architecture

Two definitions, and values passing between them

penguin is a way to run one workflow file as a live process, with any coding agent CLI. The whole model is a workflow, an adapter, and the engine that connects them.

The two concepts

There is no third. A message stream is a return value, not a definition. The view is an adapter. Agents are adapters.

🧩 Workflow

A plain TypeScript function. It orchestrates adapters, composes other workflows, and decides what the human sees. It never prints, spawns, or reads a file on its own: it touches the world only through ctx.

🔌 Adapter

A workflow's bridge to one outside thing: git, GitHub, an agent CLI, the person watching. A role, a name, and build(host) returning plain functions over plain data.

The core claim

You decide the workflow. Loops, retries, conditions, and composition are already in TypeScript, so that is what workflows are written in. When a person is needed the workflow pauses on a question; when nothing needs them it keeps moving on its own.
