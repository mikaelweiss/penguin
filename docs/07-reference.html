Reference

An Nx workspace with two projects. packages/engine is the whole of Penguin, and apps/docs serves the pages you are reading. 

penguin/
├── apps/
│   └── docs/                 this site: reads docs/ and serves it
├── docs/                     the html pages
├── packages/
│   └── engine/
│       ├── src/
│       │   ├── core/         what a workflow and an adapter are
│       │   ├── catalog/      finding and loading definitions
│       │   ├── adapters/     the builtin files view
│       │   ├── host.ts       cwd, home, state, config, shell, exec
│       │   ├── paths.ts      where penguin's folders live
│       │   ├── config.ts     reading ~/.penguin/config
│       │   ├── run.ts        one workflow file, wired and run

│       │   └── trace.ts      the run file: head, calls, outcome
│       ├── tests/            the starter catalog's tests

├── nx.json
├── tsconfig.json

What penguin exports

Definition files import penguin. A frontend imports penguin/catalog.

Name Signature Does
workflow (definition) => definition Checks the description is non-blank, then returns the object.
adapter (definition) => definition Checks role, name, description, and build.
call (ctx, child, params) => Promise<R> Parses the child's params and spawns it as its own run.
PenguinError class extends Error Penguin refusing.
RunStopped, RunCrashed class extends PenguinError How call rejects when a child was stopped, or died silently.
menuOf, menuOfSchema (shape | schema) => Menu | undefined The choices a shape names, for any frontend rendering an ask.
messageOf (error: unknown) => string The message of a caught value, whatever it turned out to be.
issuesOf (error: z.ZodError) => string One line naming every issue, for a person to read.
Channel class Channel<T> implements AsyncIterable<T> A push stream: push, end, iterate. 
interface Adapters {}

type Ctx<Params> = { params: Params } & Adapters;

type Workflow<Schema extends z.ZodObject = z.ZodObject, R = unknown> = {
  description: string;
  params: Schema;
  run(ctx: Ctx<z.infer<Schema>>): Promise<R>;
  file?: string; // workflow() fills it in, so call can spawn it
};

type View = {
  show(text: string, options?: { kind?: "tool" }): Promise<void>;
  ask: Ask;
  listen(): AsyncIterable<{ text: string }>;
};

type Menu = { choices: { label: string; value: unknown }[]; other: boolean; many: boolean };

type Adapter<A = unknown> = {
  role: string;
  name: string;
  description: string;
  build(host: Host): A;
};

type Host = {
  cwd: string;
  home: string;
  state: string;
  run: { id: string; dir: string };
  config(key: string): string | undefined;
  shell(cmd: string, options?: ShellOptions): Promise<CommandResult>;
  exec(argv: string[], options?: ExecOptions): Promise<CommandResult>;
};

type CommandResult = { code: number; stdout: string; stderr: string };

type ShellOptions = { cwd?: string; stdin?: string };

type ExecOptions = ShellOptions & {
  onOutput?: (chunk: string, stream: "stdout" | "stderr") => void;
  signal?: AbortSignal;
};

Adapters is empty on purpose. A catalog widens it by declaration merging, which is the only way ctx.vcs gets a type.

penguin/run

The entry point a frontend calls to actually run something.

Export Answers
run(file, params?, options?) Loads the workflow, validates params, wires one adapter per role through pick, wraps them in the trace, and returns what the workflow returns. Throws PenguinError on a missing or ambiguous role.
RunOptions { cwd?, catalogs?, id?, parent?, resume? }
runId() A fresh run id with its folder claimed, so a frontend knows the folder before starting.
latestRun() The newest run file, for resume.
createHost(cwd, run) A Host, for a frontend wiring adapters by hand.

Workspace conventions

  • Bun workspaces cover apps/* and packages/*. A folder becomes a project by having a package.json.
  • Nx tags declare boundaries. The engine is scope:engine and may only depend on scope:engine, enforced by @nx/enforce-module-boundaries in eslint.config.js.
  • Inside the engine, lint holds the folder boundaries too: core/ imports only zod and itself, catalog/ only core, config, and paths, builtin adapters/ only core, and only run.ts orchestrates across them. An illegal import is a build failure, not a review comment.
  • The root tsconfig.json maps penguin to packages/engine/src/core/index.ts, so definition files, examples included, type-check and lint in place.
  • bun test runs the suite: engine contracts next to their sources in src/, starter adapter tests in tests/, git against a throwaway repository and claude against recorded stream output.
  • bun run check is tsc --noEmit followed by eslint ..

Running this site

bun run docs         # nx serve docs, on http://localhost:5656

apps/docs reads the docs/ folder on every request, so an edit shows up on reload. Point it somewhere else with PENGUIN_DOCS_DIR, and change the port with PORT. A leading number on a file orders it in the sidebar and never appears in the URL or the title.
