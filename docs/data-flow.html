One run, end to end

Data flow

The commit workflow from invocation to a committed tree. Watch where each value comes from and who narrates.

Step by step

1 · Check the world first

The workflow asks vcs.dirty() before anything else. A clean tree ends the run right there with committed: false. This is the reconciler check that makes a re-run safe.

const state = await vcs.dirty({ cwd: params.dir });
if (!state.dirty) { await view.show("nothing to commit"); return …; }

2 · Open a session, start a turn

agent.open returns a session id; agent.turn sends the PICK prompt and asks for a result shaped like Commit. The turn handle is returned immediately: the work has started, but nothing is awaited yet.

3 · Stream, and choose what to narrate

The workflow reads turn.output and decides, chunk by chunk, what the person sees. Text becomes a line; a tool call becomes an indented note. Thinking chunks are dropped here. The engine never made this choice; the workflow did.

for await (const chunk of turn.output) {
  if (chunk.kind === "text") await view.show(chunk.text);
  if (chunk.kind === "tool") await view.show(`  ${chunk.text}: ${chunk.detail ?? ""}`);
}

4 · Take the typed result

await turn.value gives back { files, message }, already validated against the Commit schema. If the agent returned nothing usable, the adapter retried the turn once with a correction before this promise resolved. An empty files list is a real answer: nothing belongs in a commit, so the workflow stops.

5 · Act, through vcs

vcs.stage(files) then vcs.commit(message). Each returns { ok, reason }. A failure is data: the workflow reports the reason to the view and returns a result saying what happened. Nothing throws in the ordinary path.

6 · Report

The workflow narrates the outcome to the view and returns a plain object. A parent workflow like ship or commit-all reads that object and decides what comes next: push, or move to the next folder.

The pattern, in one line

Read the world → open a turn → forward what matters → branch on the typed result → act → report. Every penguin workflow is a variation on this, and the same shape is what makes an interrupted run safe to start over.

Running it

The starter run.ts wires this up in the foreground: load the workflow, validate params, build the starter adapters against a host, and call run(ctx).
