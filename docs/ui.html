UI

The desktop app. One line per spec.

Build

  • Tauri. React, shadcn/ui, Lucide icons.
  • The app bundles bun and the engine. Installing the app is the whole install.
  • The app starts a run by spawning the engine's child entry detached, on the bundled bun.

State

  • Every run owns ~/.local/state/penguin/runs/<id>/: run.jsonl the run writes, inbox.jsonl frontends append to, files/ holding what you paste.
  • The app is a reader plus an inbox writer. Its only state is settings.
  • Quitting the app changes nothing. Runs keep going; reopening reads the files.
  • Runs started from the CLI appear too. Same files, same tree.
  • The run tree is the parent id in each run's head line.
  • The head line records the git root, so a worktree run groups under its project.
  • A run that moves into a worktree appends a {"dir": ...} note; the newest one is the run's directory.
  • Status is derived: live pid running, pending ask needs you, closing entry done, failed, or stopped, dead pid without one crashed.
  • Stopping a run kills its process group and every run inside it, pids from their head lines.
  • Answers are {"answer": ...} lines, messages {"message": "..."} lines, appended to the run's inbox.
  • Rename appends a {"name": ...} note to the run's file; the newest one is the run's name.

Sidebar

  • Runs are grouped by project root directory.
  • A run started in a worktree lists under its git project's root.
  • Each directory lists its running workflows. Done, stopped, and crashed runs filter out.
  • A filter button on the directory row shows that project's done, stopped, and crashed runs.
  • Status dots: green running, amber needs you, gray done, red stopped or crashed.
  • A run expands to show the runs inside it, to any depth.
  • A run blocked on a question shows a badge on its row only; a collapsed ancestor carries it.
  • Hovering a carried badge shows a button that expands to the first blocked run and selects it.
  • Each directory row has a plus button that starts a new workflow there.
  • Each directory row has a settings icon that opens that project's settings.
  • Row buttons show on hover. Right click shows the same as a menu, each with icon and words.
  • Right click on a run row shows its actions: stop, rename, copy directory.
  • Directories can be added and removed.
  • A settings button at the bottom opens app settings.
  • A button shows or hides the sidebar.
  • A run row's status dot sits flush left, one column for every depth.
  • Holding cmd for half a second puts a number in place of each status dot; cmd plus a number selects that run.

Output

  • Shows the view output of the selected run only.
  • A sub-run's output shows by selecting that sub-run.
  • The input area shows only when the run is listening or blocked on a question.
  • A question pins in the input area and renders the control its shape names: yes/no, menu, multi-select, or text.
  • Choices stack in one vertical list. A caret marks the cursor. A multi-select reads as markdown checkboxes, [x] for a pick.
  • Up and down, or j and k, move the cursor. Space picks in a multi-select, enter sends.
  • Down from the last choice lands in the text field and starts typing. Up from the field goes back to the choices.
  • A menu whose shape also admits text carries an "or type an answer" field.
  • A running agent shows one activity line under the transcript: latest action and elapsed time, replaced in place.
  • Clicking it expands the recent activity stream. It leaves when the run finishes.
  • No progress bars. Structure comes from narration, liveness from the activity line.
  • A sent message shows in the transcript right away.

Attachments

  • Paste an image or a file into the input area to attach it. Dragging one onto the input area does the same.
  • The input area outlines itself while a drag hovers it.
  • Attachments preview in a row above the input: a thumbnail for an image, an icon and the file name for anything else.
  • Each preview has a button that removes it.
  • A pasted image has no path yet, so the app writes it into the run's files/ directory.
  • A text or multi-line param in the new workflow form takes a paste the same way, and previews it under that field.
  • The run's folder is claimed on that first paste, so the bytes have somewhere to land before the run starts.
  • Closing the form without starting drops a folder that never became a run.
  • A dropped file keeps the path it already has. Nothing is copied.
  • The message sends paths, never bytes: one path per line, then the typed text. The agent opens the files itself.
  • The transcript shows a sent message with the same previews.

Panels

Three buttons in the top right corner: terminal, web view, diff.

  • Terminal: opens in the selected run's directory.
  • The terminal follows the selection, and follows the run when the run changes directory.
  • Web view: a browser, with tabs.
  • Diff: file diffs for the run's directory, when it is a git directory.
  • All three can be open at once.
  • Web view and diff stack on the right; the output area keeps the left.
  • The terminal spans the full width, under everything else.
  • Drag a border to resize.
  • Each panel has a full screen button that hides the others and animates it to fill the space.
  • A full screen panel shows a button to leave full screen.
  • Full screen never covers the sidebar.

Web view

  • Tabs belong to the run. Switching runs switches the whole tab strip.
  • Back, forward, reload, an address bar, and a button that sends the page to the default browser.
  • Tabs outlive a quit. Reopening the app and selecting the run finds them where they were.
  • A run opens a url with view.open, and the adapters open what they produce: a PR made, a PR reviewed, a ticket handed in.
  • Each url is a tab. A url a tab already holds is selected, not opened twice.
  • A url opened while you watch another run waits. Switching to that run opens the panel on it.
  • The empty state lists the local servers answering with a page, by the process holding each port.
  • A link clicked in the terminal opens here.
  • The page is a native view above everything the app draws, so it hides itself while a dialog is up.
  • Only the selected run's tabs cost a page. A tab loads when first looked at and keeps its state until the tab closes or the run is left.

New workflow

  • A sheet to search and pick a workflow.
  • Workflows are sorted by catalog.
  • The run's directory is the project it started from, never a param.
  • Picking a workflow with params asks for them, then starts the run. One without params starts on the pick.
  • Pasting a file onto a text or multi-line param attaches it. The path rides the value, one path per line, then the typed text.
  • The sheet's data comes from an engine describe run: each workflow's name, description, and params as JSON Schema, printed as JSON.

Catalogs

  • starter: the package's examples.
  • home: ~/.penguin workflows, skills, adapters. Yours, every project.
  • project: .penguin workflows, skills, adapters. In git.
  • project local: same, kept out of git.
  • worktree: the .penguin of the project's other git checkouts, so a workflow written on a branch is startable before it merges. The row says which checkout, and starting it runs in that checkout.
  • A branch may only add a name to the runs of other checkouts. Its adapter runs there only once a config line names it and nothing else claims that role, its skill is ignored when another catalog supplies that name, and a half-written file on a branch is skipped rather than breaking the project. In its own checkout's runs it is simply the project's.
  • A skill is a folder under a catalog's skills/ holding a SKILL.md, per the Agent Skills spec: name and description frontmatter, instructions below.

Project settings

  • A modal with a sidebar: main settings, workflows, skills, adapters.
  • Main settings holds the project's dreaming toggle.
  • The other tabs list what the project has of each.

App settings

  • A sheet with a sidebar of sections, rows of settings. Shift cmd comma opens it.
  • Holds the global dreaming toggle.
  • Light and dark, with a toggle.
  • Holds where links open: the web view, or the default browser.
  • Holds whether a url a run opens also shows the web view. On by default; off still makes the tab.
  • Holds the worktrees directory. Default ~/.penguin/worktrees/<project>/<run>.
  • Holds the default agent adapter. Both write ~/.penguin/config.
  • App-only settings, the directory list and theme, live in Tauri's app config dir.

Dreaming

  • A workflow that runs in the background, suggesting improvements to your workflows and new ones from your patterns.
  • Behind a feature flag, hidden until the design settles.
  • Off by default. On globally or per project.
  • A project's dreams show a dot on that project's settings icon; global dreams on the app settings button.
  • Inside settings, a dot marks the dreams row. Clicking it shows the suggestions.

Command palette

  • Switches runs, starts workflows, toggles panels.
  • Opens with cmd K, or the button next to the settings button.
  • Workflows, panels, and settings come first; runs sit at the bottom.
