Penguin

Penguin runs a workflow you wrote as a live process. The workflow is plain TypeScript. Adapters give it a way to touch git, an agent CLI, and you. There is no third concept.

The two definitions

Workflow Adapter
Job Decide what happens and what a person sees Reach one outside thing
Sees ctx: validated params, one entry per installed role host: cwd, state, shell, exec
Knows about Roles, never implementations One outside thing, never another adapter
Composes by Calling another workflow Nothing. Adapters do not compose.
Lives in src/core/workflow.ts src/core/adapter.ts

Anything that looks like a third concept is one of these two wearing a hat. A message stream is an adapter function that returns an AsyncIterable. The person watching the run is an adapter with the role view. An agent CLI is an adapter with the role agent. The engine has never heard of any of them.

How a run fits together

  ┌───────────────────────────────────────────────┐
  │  workflow                                     │
  │    validated params, calls ctx.<role>         │
  └───────────────────────┬───────────────────────┘
                          │  ctx
  ┌───────────────────────┴───────────────────────┐
  │  adapters      view   vcs   agent   github    │
  └───────────────────────┬───────────────────────┘
                          │  host: cwd, state, shell, exec
  ┌───────────────────────┴───────────────────────┐
  │  the outside   a terminal, git, claude, an API│
  └───────────────────────────────────────────────┘

A workflow reaches the world only through ctx. It never prints, never parses argv, never spawns a process. An adapter reaches the world only through host. It cannot write to the view, cannot ask a question, and cannot call another adapter.

The workflow is the only orchestrator and the only narrator. To know what a run will print, you read one file.

Roles and names

An adapter declares a role, which is what it is on ctx, and a name, which is which implementation it is. A workflow calls ctx.vcs.commit(...) and never learns whether git or jj answered. 

role: "vcs"     name: "git"        →  ctx.vcs
role: "agent"   name: "claude"     →  ctx.agent
role: "view"    name: "files"      →  ctx.view

Install two implementations of one role and you pick a default. See The engine.

Run one

bun packages/engine/examples/run.ts \
  packages/engine/examples/workflows/commit.ts '{"dir":"."}'

examples/run.ts is the smallest frontend there is. It loads one workflow file, parses its params, builds the starter adapters against a host, and awaits run(ctx). Almost everything Penguin does happens in the workflow file, not in the runner. The starter catalog installs five agent adapters, so pick one first: write agent claude to ~/.penguin/config.
