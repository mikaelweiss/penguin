Concept 1

Workflows

A pure script that orchestrates adapters and decides what people see. The only orchestrator, the only narrator.

The shape

A workflow is a plain object: a description, a Zod params schema, and run(ctx).

// packages/engine/src/core/workflow.ts
export type Workflow<Schema, R> = {
  description: string;
  params: Schema;                // a Zod object
  run(ctx: Ctx<z.infer<Schema>>): Promise<R>;
};

export type Ctx<Params> = { params: Params } & Adapters;

The workflow() helper does one thing at definition time: it rejects a workflow with no description. Everything else about a run is just the function you wrote.

ctx is the whole world

The validated params, plus one entry per installed adapter role. That is all it is.

Invariant

Nothing shows a person anything unless workflow code sent it. The workflow calls adapter functions, consumes the streams they return, and decides what reaches view.

Composition is a function call

call parses the child's params and runs it with the same ctx. Parallel children are Promise.all over call.

// commit-all.ts - run one child workflow per folder, all at once
import { call, workflow } from "penguin";
import commit from "./commit.ts";

export default workflow({
  description: "commit every listed folder, all at once",
  params: z.object({ dirs: z.array(z.string()).min(1) }),

  async run(ctx) {
    const results = await Promise.all(
      ctx.params.dirs.map(async (dir) => ({
        dir, done: await call(ctx, commit, { dir }),
      })),
    );
    await ctx.view.show(`committed ${results.length} folders`);
    return results;
  },
});

Workflows are reconcilers

They inspect the world through adapters before acting, and act only on what is missing.

Because a workflow checks the world first, resuming an interrupted run is running the workflow again. Its own checks skip what is already done. The world is the state store: there is no journal and no replay.

Pausing on a person

When a workflow needs a decision, it awaits view.ask and does not move until the answer arrives. When it does not, it keeps running on its own. The distinction is built into the code, not something you scroll to discover.

// ship.ts - commit, then pause for a yes/no before pushing
const answer = await view.ask(`Push ${head.branch} to origin? (yes/no)`, z.enum(["yes", "no"]));
if (answer === "no") return { ...done, pushed: false };
const pushed = await vcs.push(head.branch, { cwd: params.dir });
